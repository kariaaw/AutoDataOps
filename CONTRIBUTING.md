# Contributing to AutoDataOps

Thank you for your interest in AutoDataOps.

AutoDataOps is an enterprise-oriented data reliability
and verified recovery platform under active development.

## Engineering Standards

All contributions should follow these principles:

- Write clean, readable, and maintainable code.
- Follow the established project architecture.
- Add automated tests for new functionality.
- Document important architectural decisions.
- Handle errors explicitly.
- Avoid unnecessary dependencies.
- Never commit secrets or customer data.
- Maintain backward compatibility when possible.

## Code Quality

Go contributions should pass:

- Code formatting checks
- Go static analysis
- Unit tests
- Race detector tests
- Application build verification

## Bug Reports

Include reproduction steps, expected behavior,
actual behavior, and sanitized diagnostic logs.

## Feature Requests

Explain the problem, proposed solution,
alternatives, and measurable acceptance criteria.

## Pull Requests

Keep changes focused and reviewable.

Explain implementation decisions and provide
appropriate automated tests.

## Licensing

AutoDataOps uses AGPL-3.0-only.

Separate commercial licensing may be offered.

The contributor licensing process is not yet finalized.

External code contributions may be deferred until
the required licensing permissions are established.

## Security

Do not report security vulnerabilities publicly.

Refer to SECURITY.md for reporting guidance.

## Project Status

AutoDataOps is under active development.

Production readiness is not yet claimed.
